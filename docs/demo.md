# Interview demonstration (3–5 minutes)

**Opening:** Practice Room is an AI learning assistant for self-taught musicians. I scoped it to piano, guitar and bass, designed a reusable teaching workflow, and separated musical calculation from generative explanations. I used AI-assisted development to implement and test the prototype.

1. In the installed plugin (or reference-based fallback), ask: "I'm new to bass, like melodic post-punk, and have 15 minutes a day. Start me with a simple lesson." Show the practical plan, notes and success criteria.
2. Follow up: "I can only do two clean repetitions at 60 BPM, and the last stretch is uncomfortable." Expect a slower or simplified exercise, no forced stretching or invented performance score.
3. Ask: "Show me Ebmaj7 first inversion on piano, then an A minor pentatonic bass fretboard through fret 7." Compare with CLI results. Correct Ebmaj7 inversion: G, Bb, D, Eb; bass open A is a root.
4. Ask for an original 8-bar 75 BPM A minor bass exercise. If host execution is unavailable, use the existing `examples/bass-practice.mid` (generated by the engine) and its JSON score; open in a DAW and mute the practice part.
5. Show the GitHub repository or local source, automated tests and the manual eval checklist. Mention no external API key is needed, and real-time listening is intentionally excluded.

**What to say if asked about the screening:** "That question prompted me to turn the idea into a working prototype. Since our call, I've developed the skills, music engine and tests. Here's what I can demonstrate today."

**Tradeoffs:** A skills-only plugin keeps cost and setup low, with text fallbacks on hosts lacking script execution. Deterministic tools reduce common music-theory errors, but teaching quality still needs human evaluation. Portable progress avoids building a backend or collecting personal information prematurely.
